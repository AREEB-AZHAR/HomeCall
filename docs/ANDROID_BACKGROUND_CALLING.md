# Android background calling

Availability, ringing and active calls use notification ID 21 through startForeground. The incoming CallStyle notification uses the high-importance incoming channel and is attached to the foreground service. Returning to availability replaces the call notification on the same ID. The Dart call deadline ends unanswered calls. Android must retain a valid foreground notification throughout this sequence.

Setup starts the local listener and a visible connected-device foreground service. An application-scoped Flutter engine receives native callbacks while the process survives. The app holds a multicast lock for discovery. Destroying the service stops advertising, releases the lock and closes the listener.

HomeCall uses the platform self-managed ConnectionService available from API 26. It registers a PhoneAccount with MANAGE_OWN_CALLS, asks Telecom to place or admit each call, and sets audioModeIsVoip. Telecom can refuse a call when another system call takes priority. Audio route requests go through the Telecom connection. Incoming notifications are posted in response to onShowIncomingCallUi. Android 12 and later use CallStyle. Older versions receive category-call notifications with actions. Ringtone playback follows the incoming-call channel and the user's sound settings. [Android ConnectionService](https://developer.android.com/reference/android/telecom/ConnectionService)

Answer opens the call activity for the specified session. Decline delivers a private broadcast. The answer activity requests lock-screen visibility where supported. Full-screen intent permission is deliberately omitted. Android can require unlock or suppress heads-up presentation according to device policy, DND, notification settings and OEM behavior. [Call notifications](https://developer.android.com/develop/ui/views/notifications/call-style)

Android 13 and later request notification permission alongside microphone permission. Android 14 and later check foreground service types and while-in-use microphone access. The manifest declares connectedDevice, microphone and phoneCall, with type-specific permissions. An active call promotes the service and handles rejected microphone access as a failed call. On Android 15 and 16 availability starts through the app. There is no boot receiver. Reopen after reboot, force-stop, process termination or an OEM battery restriction. The service requests START_NOT_STICKY. There is no external wake-up mechanism. [Android foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types)

**If the second phone does not ring:** first place a foreground call. Check the ongoing availability notification, grant microphone and notification access in Android Settings, enable the Incoming calls channel with sound and lock-screen visibility, and repeat with battery saver disabled as a diagnostic. Record Android version and manufacturer if baseline works but locking the phone breaks delivery.
